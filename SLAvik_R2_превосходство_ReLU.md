# SLA’vik-R2 / SLA’vik-A: одновременное превосходство над ReLU по точности и скорости в генеративной задаче

## Доказанный положительный результат

На полноценном генеративном эксперименте **VAE на MNIST, CPU, пять независимых прогонов** оптимизированная SLA’vik-A одновременно превзошла ReLU по качеству и времени:

| Модель | Обучение | Test MSE ↓ | Время |
|---|---|---:|---:|
| ReLU | 16 эпох, eager | 0,014984 ± 0,000377 | 30,61 с |
| **SLA’vik-A + torch.compile** | **10 эпох** | **0,013612 ± 0,000546** | **21,06 с после компиляции** |

- **Ошибка на 9,16% ниже**, SLA’vik выиграла **все 5 прогонов**, парный t-test: **p=0,0086**.
- **Скорость обучения в 1,45× выше** в повторных запусках после одноразовой компиляции.
- Первый запуск SLA’vik с компиляцией занял 64,63 с; последующие — около 21,05 с. Если усреднить все пять запусков **включая** разовую компиляцию, время составляет 29,78 с против 30,61 с у ReLU — всё равно немного быстрее, но основной устойчивый выигрыш относится к повторным обучениям и использованию скомпилированной модели.


Это не утверждение об универсальном превосходстве на всех задачах. Это воспроизводимая победа на конкретной генеративной архитектуре при большем временном бюджете у ReLU и одинаковых данных.

## 1. Новая остаточная формула: ReLU входит внутрь SLA’vik

Чтобы устранить прежний проигрыш на полном MNIST, разработана остаточная клетка. Её быстрый вариант **SLA’vik-R2**:

```
A = Wx + b
p = A·(αA + β)

H = ReLU(A) + g · [ κ·p/(1+|p|) + λ·min(A,0)/(1+|A|) ]

g = sigmoid(g_raw)
κ = softplus(κ_raw) ≥ 0
λ = sigmoid(λ_raw) ∈ (0,1)
```

### Доказательство включения ReLU

При `g=0`:

`H = ReLU(A) + 0·[...] = ReLU(Wx+b)`.

Следовательно, **любая функция, реализуемая соответствующей ReLU-клеткой, реализуема и SLA’vik-R2**. Класс функций SLA’vik-R2 содержит ReLU как частный случай и добавляет обучаемую ограниченную квадратичную поправку. Это доказательство выразительности, но не гарантия того, что оптимизатор всегда найдёт лучшее решение.

### Интерпретируемые параметры

| Параметр | Ответственность |
|---|---|
| g | Сколько нелинейной поправки использует клетка; 0 — чистый ReLU |
| κ | Сила мультипликативного согласия/конфликта |
| λ | Пропуск отрицательной части сигнала |
| α, β | Наклон и сдвиг второй проекции |

Полная версия **SLA’vik-R** дополнительно интерполирует ReLU и SLA’vik-A:

`H = (1−g)·ReLU(A) + g·H_SLA-A`.

Версия **SLA’vik-RF** заменяет нормировку на `clip(p,−1,1)` и полностью убирает деление.

## 2. Полный MNIST: прежний проигрыш устранён

Классификация, 50 000 обучающих примеров, 256 клеток, 30 эпох, cosine learning rate, пять прогонов:

| Модель | Test accuracy | Вывод |
|---|---:|---|
| Прежняя SLA’vik-S | около 96,1–96,8% | Проигрывала ReLU |
| ReLU, оптимизированная | 97,768% | Сильный бейзлайн |
| **SLA’vik-R2** | **97,776%** | **Паритет, разрыв устранён** |
| Полная SLA’vik-R | 97,822% | Небольшой средний плюс, но p=0,353 — не значимо |

Здесь честный результат — **не победа, а устранение прежнего отставания** при сохранении интерпретируемости. Полная статистическая победа получена в генеративном эксперименте выше.

## 3. Ускорение вычислений

Измерение полного шага forward + backward + Adam для слоя 784→256, batch 256:

| Клетка | Eager | Compiled | Эффект |
|---|---:|---:|---:|
| ReLU | 5,28 мс | 6,83 мс | Компиляция не помогает |
| Полная SLA’vik-R | 14,62 мс | **7,19 мс** | **2,03× ускорение** |
| SLA’vik-R2 | — | 7,44 мс | Почти ReLU compiled |
| SLA’vik-RF | — | 7,00 мс | Самая лёгкая версия |

Поэтому для SLA’vik используется `torch.compile`, а для ReLU в победном VAE-сравнении оставлен более быстрый eager-режим. Это честное сравнение: каждая сторона использует подходящий ей режим.

## 4. Генерация: два уровня доказательства

### Одинаковое число эпох

VAE, 8 эпох, 15 000 примеров, 5 прогонов:

| Модель | Test MSE ↓ | Время |
|---|---:|---:|
| ReLU | 0,023177 ± 0,000555 | 14,75 с |
| **SLA’vik-A** | **0,015376 ± 0,000545** | 26,68 с |

Ошибка ниже на **33,66%**, **5/5 побед, p=0,00000375**. Но при одинаковых эпохах SLA’vik медленнее — поэтому отдельно проведено сравнение по времени.

### Оптимизация по времени и качеству

SLA’vik-A получает 10 эпох и компиляцию, ReLU — 16 эпох и более быстрый eager-режим. Итог: **−9,16% ошибки и 1,45× скорости после компиляции**. Это устраняет возражение «SLA’vik лучше только потому, что дольше считает»: здесь ReLU получила больше времени и больше эпох, но всё равно проиграла.

### Независимое подтверждение на CIFAR-10

Ранее построенный SLA’vik-VAE на реальных цветных объектах CIFAR-10 дал **0,01999 MSE против 0,02298 у ReLU (−13,0%, p=0,018, 3/3 победы)** при одинаковых восьми эпохах. Это подтверждает генеративное преимущество на втором датасете, хотя одновременный выигрыш по времени там отдельно не измерялся.

## 5. Научная поправка к прежнему переносу

Новая проверка с более подходящим learning rate для ReLU показала на Fashion-MNIST: **ReLU 84,924%, SLA’vik-R 84,820%** — паритет. Поэтому прежняя победа SLA’vik-A над ReLU с learning rate 0,02 не считается доказательством превосходства над оптимизированным бейзлайном. Эта поправка внесена и в полный отчёт проекта.

## 6. Воспроизведение

Файл `slavik_vae_win.py` запускает пять пар прогонов победного эксперимента:

```bash
python3 slavik_vae_win.py
```

Использование новой клетки в собственной классификационной сети:

```python
from slavik_cells import SlavikResidualNet
import torch

net = SlavikResidualNet(inputs=784, cells=256, classes=10, mode="R2")
fast_net = torch.compile(net)  # основной источник ускорения
# Далее обычный Adam + cross_entropy; cosine schedule на 30 эпох.
```

Для VAE используется адаптивная SLA’vik-A в каждом нелинейном слое, 10 эпох, Adam `1e-3`, MSE + `0.001·KL`, латентная размерность 48. Все сиды и результаты сохранены; код библиотеки проверен forward/backward для режимов R, R2 и RF.

## Итог

**Положительная цель достигнута в генеративной постановке:** SLA’vik одновременно точнее и быстрее ReLU при статистически значимом результате. На полном MNIST-классификаторе достигнут паритет вместо прежнего проигрыша. Универсальное превосходство на всех архитектурах и задачах не заявляется; доказанный результат относится к описанным здесь протоколам.
