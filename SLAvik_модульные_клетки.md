# SLA’vik-S: управляемая система из клеток и функциональных блоков

## Что построено

Система переведена от единого непрозрачного классификатора к двум уровням управления. На первом уровне находятся **клетки SLA’vik-S**, для каждой из которых измеряются активация по классам, специализация, вклад в решения и последствия отключения. На втором — **парные функциональные блоки**: каждый блок имеет заранее заданную ответственность, например «отличать цифру 3 от цифры 5». Блоки обучаются и дообучаются независимо, а итоговое решение получается их голосованием без обучаемого глобального выходного слоя.

Это не устраняет численные параметры внутри клеток, но делает их **наблюдаемыми и управляемыми через поведение**. При этом не доказано, что каждая клетка соответствует отдельному человеческому понятию: специализация является измеренной статистикой на конкретных данных, а не встроенным смысловым описанием.

## 1. Вычислительная клетка

Для входа `x` клетка сначала строит одну проекцию:

`A = Wx + b`,

а вторая проекция получается из первой без отдельной матрицы весов:

`B = αA + β`.

Активация SLA’vik-S равна:

`H = max(A+B, 0) + λ·min(A+B, 0)/(1+|A+B|) + κ·AB/(1+|AB|)`.

В проверенной конфигурации используются `α=0,37`, `β=0,11`, `κ=2`, `λ=0,15`. Первый член передаёт положительный сигнал, второй сохраняет ослабленный отрицательный отклик, а третий измеряет согласие или конфликт двух проекций. Благодаря связи `B=αA+β` требуется только одна входная матрица `W`.

## 2. Как снимается «завеса магии»

Для клетки `j` вычисляются четыре разные характеристики. Их нельзя смешивать: высокая активация ещё не означает положительный вклад в ответ.

| Показатель | Формула или операция | Что он позволяет понять |
|---|---|---|
| Активация по классу | `E[H_j | class=c]` | На каких примерах клетка реагирует сильнее |
| Специализация | `max_c E[H_j | c] / mean(E[H_j])` | Насколько отклик концентрируется на отдельных классах |
| Вклад в класс | `E[H_j] · out[c,j]` | Какие ответы клетка поддерживает или подавляет |
| Важность | Изменение точности после `out[:,j]=0` | Что фактически происходит с системой без клетки |

Карта активаций показывает, что разные клетки по-разному реагируют на классы. Однако окончательное решение зависит также от знака и величины выходной связи, поэтому аудит обязательно включает вклад и контрольное отключение.


### Результат контролируемого отключения

В эксперименте с монолитной SLA’vik-S исходная validation accuracy составила **95,80%**. Клетки отключались группами по измеренной важности.

| Отключено клеток | Validation accuracy |
|---:|---:|
| 0 | 95,80% |
| 4 | 95,58% |
| 8 | 94,85% |
| 12 | 92,51% |
| 16 | 87,91% |
| 24 | 82,34% |

Это демонстрирует возможность количественно оценить цену удаления. Отдельные отключения в аудите также выявили шесть клеток, после обнуления выходных связей которых точность временно возрастала. Это кандидаты на дальнейшую проверку или удаление, а не доказательство их бесполезности на всех данных.

## 3. Функциональные блоки вместо одного глобального решения

Для задачи с десятью цифрами созданы **45 парных блоков** — по одному для каждой неупорядоченной пары классов. Внутри каждого блока находятся четыре клетки SLA’vik-S и локальный выход на два решения. Блок `3/5`, например, видит только примеры классов 3 и 5 и не изменяет параметры блоков других пар.

Схема системы:

`вход → независимые PairBlock(i,j) → локальные голоса → сумма голосов → класс`

Глобальный обучаемый агрегатор отсутствует. Если блок ошибается, его можно проверить и дообучить отдельно. Если возникает новая проблемная пара классов, можно добавить новый блок, не переобучая всю сеть.

### Измеренные результаты

| Конфигурация | Результат |
|---|---:|
| Средняя accuracy отдельных парных блоков | 99,7779% |
| Голосование 45 блоков, validation | 95,34% |
| Обычная монолитная SLA’vik-S, validation | 95,80% |
| Блок 3/5 до локального дообучения | 99,115% |
| Блок 3/5 после локального дообучения | 99,334% |
| Общая validation после этого дообучения | 95,34% |


Локальное дообучение блока 3/5 действительно улучшило его собственную точность, не меняя остальные блоки. Общая точность при этом не выросла: локальное улучшение одной пары не обязано менять итоговое голосование на всей выборке. Модульная версия пока уступает монолиту на **0,46 процентного пункта**, зато предоставляет явные границы ответственности и независимое редактирование.

## 4. Практические операции управления

Реализация находится в `slavik_cells.py` и поддерживает следующий цикл:

1. **Аудит:** получить для каждой клетки наиболее активные, поддерживаемые и подавляемые классы.
2. **Проверка причинности:** отключить клетку и повторно измерить качество на отдельной контрольной выборке.
3. **Локальное обучение:** обучить только выбранный `PairBlock` на примерах его двух классов.
4. **Сборка:** передать блоки в голосование без глобального обучаемого слоя.
5. **Ревизия:** сравнить локальные и общие метрики до и после изменения; откатить блок, если общий результат ухудшился.

Минимальный пример:

```python
from slavik_cells import PairBlock, train_pair_block, vote

block_35 = PairBlock(inputs=784, class_a=3, class_b=5, cells=4)
mask = (train_labels == 3) | (train_labels == 5)
loss_history = train_pair_block(
    block_35,
    train_x[mask],
    train_labels[mask],
    epochs=20,
)

# Аудит клеток внутри только этого блока.
report = block_35.core.cell_report(train_x[mask], train_labels[mask])

# Все блоки принимают участие в голосовании, но глобальный слой не обучается.
predicted = vote(blocks, validation_x, num_classes=10)

# Контролируемое отключение клетки внутри конкретного блока.
block_35.core.ablate_cells([0])
```

Перед реальным отключением следует сохранить копию состояния блока. Метод `ablate_cells` намеренно меняет выходные связи, поэтому восстановление выполняется из сохранённого `state_dict`.

## 5. Что доказано экспериментом и что ещё предстоит улучшить

Работоспособность модульного принципа подтверждена на текущей задаче классификации: парные блоки обучаются раздельно, их ответственность задана явно, голосование работает без глобального обучаемого агрегатора, а влияние клеток измеряется прямым вмешательством. Интерфейс дополнительно проверен на запуск: аудит принимает как PyTorch-тензоры, так и NumPy-массивы, локальное обучение снижает ошибку отдельного блока, а голосование не ограничено десятью классами.

Универсальное превосходство над ReLU, монолитной SLA’vik-S или другими архитектурами этим экспериментом не доказано. Также не доказано ускорение всей модульной системы: 45 отдельных блоков могут требовать больше вычислений, чем один компактный классификатор. Следующие технические задачи — ускорить пакетное выполнение парных блоков, автоматически создавать блоки по устойчивым ошибкам, добавить версионирование и откат изменений, а также сократить разрыв в точности между голосованием и монолитом.
